# Telegram-дайджест и настроение рынка

Личный owner-only бот формирует компактные аналитические записки за последние 24 часа:

- `Дайджест сейчас` — главное из каналов `Посты` с сопоставлением сообщений папки `Чаты`;
- `Настроение сейчас` — настроение участников чатов, его драйверы и расхождение с каналами;
- `Статус` — состояние MTProto, Codex, папок, расписания и последних запусков.

Автоматическое расписание в `Europe/Samara`: дайджест в 15:00, настроение в 16:00.

Сервис не использует PostgreSQL и не собирает сообщения постоянно. В момент запуска он читает
точное окно `(текущее время - 24 часа, текущее время]`, анализирует данные через Codex CLI
через авторизацию ChatGPT в Codex CLI и отправляет результат владельцу. Сырые тексты удаляются
после анализа. В volume состояния сохраняются исследовательские кластеры, точные короткие цитаты,
источники и проверенные записки за 35 дней. Это нужно для сравнения с предыдущими сутками.

API-ключ не используется и не создаётся. Прямых вызовов Responses API нет. Используются лимиты
Codex вашего ChatGPT-аккаунта; резервная модель тоже расходует эти лимиты, а не API-баланс.

## Аналитический конвейер

1. **GPT-6 Luna high** читает все текстовые сообщения пакетами, отмечает шум и рекламу,
   выделяет факты, мнения, прогнозы и эмоции, объединяет события и сохраняет цитаты.
2. **Luna research layer** объединяет кластеры между пакетами и сравнивает с предыдущими
   сутками. Копии одного первоисточника не считаются независимыми подтверждениями.
3. **GPT-6 Astra high** получает структурированное исследование и предыдущую записку.
   Выделяет 3–5 ключевых тем, связи, причины изменения настроения, споры и триггеры.
   Тысячи сырых сообщений Astra не получает.
4. **Luna audit** проверяет выводы по оригиналам/точным выдержкам и истории. Только прошедший
   аудит отчёт сохраняется и отправляется. При неподтверждённых утверждениях выпуск блокируется.

Для аналитического этапа резервная цепочка: `gpt-6-astra → gpt-6-sol → gpt-5.6-luna`.
Для массового исследования: `gpt-6-luna → gpt-5.6-luna`. Переключение происходит при ошибке
доступности/таймауте Codex, но не при нарушении JSON-схемы или провале аудита. Выбранная модель
и использование резерва указаны в Telegram-отчёте и внутренней истории.

В записке: период и объём изученного, настроение и его изменение, главное, закономерности,
существенные разногласия, что изменит картину, главный вывод и мысль дня. Каждое утверждение
имеет тип: факт, мнение источников, прогноз, реакция, интерпретация модели или вывод из данных.
На основную тему выводятся максимум четыре ссылки. Полный набор доступен через `/sources`;
последние проверенные записки — `/history`.

Для сравнения берётся последний отчёт того же вида с окончанием не позднее начала текущих
суток и разрывом не более 6 часов. Перекрывающиеся ручные выпуски и старая история не считаются
«вчера». Точные даты базы сравнения показываются. Если её нет, изменение не выдумывается;
если нет содержательных сообщений чатов, индекс настроения не рассчитывается.

## Подготовка Telegram

В официальном приложении Telegram того же аккаунта создайте две папки:

1. `Посты` — добавьте нужные каналы. Группы из этой папки будут пропущены.
2. `Чаты` — добавьте нужные группы. Каналы из этой папки будут пропущены.

Закреплённые и обычные включённые источники объединяются, исключённые из папки не читаются.

## Конфигурация

```bash
cd /opt/market-digest
cp .env.example .env
nano .env
chmod 600 .env
```

Обязательные секреты:

```dotenv
TELEGRAM_API_ID=123456
TELEGRAM_API_HASH=...
TELEGRAM_PHONE=+79XXXXXXXXX
BOT_TOKEN=...
OWNER_TELEGRAM_ID=123456789
```

Основные неизменяемые настройки:

```dotenv
OPENAI_MODEL=gpt-5.6-luna
OPENAI_REASONING_EFFORT=high
RESEARCH_MODEL=gpt-6-luna
ANALYST_MODEL=gpt-6-astra
ANALYST_FALLBACK_MODEL=gpt-6-sol
CODEX_REQUIRED_VERSION=0.153.0
RESEARCH_HISTORY_PATH=/data/state/research.json
APP_TIMEZONE=Europe/Samara
DIGEST_HOUR=15
DIGEST_MINUTE=0
SENTIMENT_HOUR=16
SENTIMENT_MINUTE=0
POSTS_FOLDER_NAME=Посты
CHATS_FOLDER_NAME=Чаты
```

Не публикуйте `.env`, Telegram session и каталог Codex auth.

## Первый запуск

```bash
docker build -t market-digest:mvp .
docker compose config --quiet
docker compose config --services
docker compose run --rm app python -m market_digest check-config
```

Один раз авторизуйте обычный Telegram-аккаунт с интерактивным терминалом:

```bash
docker compose run --rm app python -m market_digest login
```

Один раз авторизуйте Codex через подписку ChatGPT:

```bash
docker compose --profile setup run --rm codex-login
```

Сохранённую авторизацию повторять не нужно. Проверка входа без обращения к модели:

```bash
docker compose run --rm app codex login status
```

Необязательная команда `python -m market_digest codex-preflight` делает реальные
запросы и расходует лимиты. По текущему решению владельца её не запускаем.
Если позднее её запустить осознанно, ожидаемое завершение:

```text
Codex route ready: gpt-6-luna/high
Codex route ready: gpt-6-astra/high
Codex research and analyst routes: Structured Outputs preflight passed.
```

Запуск единственного постоянного контейнера:

```bash
docker compose up -d --remove-orphans app
docker compose ps
docker compose logs --no-color --tail=200 app
```

После запуска отправьте боту `/start`, чтобы обновить постоянную клавиатуру.

## Эксплуатация

```bash
docker compose ps
docker compose logs --no-color --tail=200 app
docker compose restart app
docker inspect --format='{{.Name}} {{.State.Status}} restarts={{.RestartCount}}' market-digest-app-1
```

`Статус` показывает:

- доступность MTProto и Codex;
- наличие и число допустимых источников в `Посты` и `Чаты`;
- текущую задачу;
- время, длительность, количество источников/сообщений и безопасный код последнего результата;
- расписание 15:00 и 16:00 по Самаре.

Одновременно выполняется только один анализ. Повторное нажатие во время активного отчёта не
запускает второй Codex-процесс. Если за 24 часа нет подходящих сообщений, бот сообщает об этом и
Codex не вызывается.

## Volumes и резервное копирование

Новый Compose использует:

- `market-digest_telegram_session` — MTProto-сессия;
- `market-digest_codex_auth` — авторизация Codex;
- `market-digest_runtime_state` — операционные метаданные и проверенная исследовательская история.

Посмотреть точные имена:

```bash
docker volume ls --filter label=com.docker.compose.project=market-digest
```

Перед переносом остановите `app` и архивируйте volumes средствами Docker/хостинга. Telegram session
равноценна доступу к аккаунту, поэтому храните резервную копию как секрет.

Никогда не выполняйте `docker compose down -v`: ключ `-v` удаляет авторизации и состояние. При
переходе со старой PostgreSQL-версии также не удаляйте `market-digest_postgres_data`; это точка
отката до отдельного подтверждения владельца.

## Безопасное обновление со старой версии

1. Сохраните старый `docker-compose.yml`, ID образа и имя PostgreSQL volume.
2. Загрузите код в `/opt/market-digest`, не перезаписывая `.env` и volumes.
3. До остановки старых контейнеров выполните build, `config` и `check-config`.
4. Остановите только старые контейнеры `app`, `worker`, `postgres`; не используйте `down -v`.
5. Запустите `docker compose up -d --remove-orphans app` с новым Compose.
6. Проверьте логи, restart count, кнопку `Статус` и оба ручных отчёта.
7. Оставьте старый PostgreSQL volume до завершения периода наблюдения.

Каталог `/root/bots` не относится к этому проекту: не копируйте туда файлы и не меняйте его
сервисы при развёртывании `/opt/market-digest`.

## Ограничения

- анализируются только текст и подписи к медиа, без OCR, аудио и видео;
- индекс отражает настроение участников выбранных чатов, а не направление цены;
- результаты не являются инвестиционной рекомендацией;
- полные исходные сообщения не хранятся; кластеры, выдержки и проверенные отчёты сохраняются 35 дней;
- доступ к кнопкам разрешён только `OWNER_TELEGRAM_ID`.

Лимиты Plus не безграничны; при недоступности всех разрешённых моделей бот выдаёт уведомление.
Крупный структурированный результат, который невозможно безопасно вместить в контекст,
завершает запрос ошибкой без молчаливого усечения. При аудите длинных оригиналов используются
точные цитаты с окружающим контекстом. Недостаточность этого контекста должна отклонять вывод.
Проверки по схеме и AI-аудит снижают риск ошибок, но не доказывают истинность Telegram-публикаций.

## Обновление уже работающего экземпляра

Сохраните `.env` и volumes. Добавьте новые модельные настройки из примера, затем:

```bash
docker build -t market-digest:mvp .
docker compose run --rm app python -m market_digest check-config
docker compose run --rm app codex login status
docker compose up -d app
docker compose logs --tail=100 app
```

Повторный вход не нужен при сохранённом `codex_auth`. Dockerfile закреплён на CLI 0.157.1;
приложение принимает CLI не ниже 0.153.0. Проверить локальную версию и способ входа:

```bash
codex --version
codex login status
python scripts/check_codex_models.py
```

Список моделей не гарантирует доступный остаток лимита; `codex-preflight` делает короткие
реальные вызовы обоих этапов и показывает фактически выбранный маршрут.
Эта проверка не обязательна для запуска и сейчас отключена от порядка обновления,
чтобы не расходовать лимиты. Unit-тесты используют искусственные ответы моделей.
Запуск `app` включает обычное расписание: в 15:00/16:00 будут реальные отчёты.
Если лимиты пока нужно сохранить полностью, не запускайте контейнер `app`.

Официальные справки: [модели Codex](https://learn.chatgpt.com/docs/models),
[автоматические запуски](https://learn.chatgpt.com/docs/non-interactive-mode).
