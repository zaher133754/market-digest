## Приёмка на сервере

Сохранить существующие `.env`, Telegram-сессию и volume `codex_auth`.

```bash
docker build -t market-digest:mvp .
docker compose run --rm app python -m market_digest check-config
docker compose run --rm app codex login status
docker compose up -d app
docker compose logs --tail=100 app
```

По указанию владельца живые проверки анализа/сбора сейчас НЕ проводятся: лимиты
нужно сохранить. `codex-preflight` тоже не запускать — он расходует лимиты.
Следующие действия описывают будущую приёмку после отдельного решения владельца.
Запуск app активирует боевое расписание и не является безлимитной проверкой.

Проверить «Статус», затем «Дайджест сейчас». В отчёте должны быть максимум пять
главных тем, явные типы утверждений, максимум четыре ссылки на тему, выбранная
аналитическая модель. Первому выпуску разрешено не иметь сравнения со вчера.
Через сутки повторить: прежний индекс должен быть взят из исследовательской
истории, а не создан заново моделью. `/history` и `/sources` показывают историю
проверенных записок и полный каталог использованных публикаций соответственно.

Семантические случаи для живой приёмки —
`tests/fixtures/analytical_eval_cases.jsonl`. Успешный контрактный тест не означает,
что модель прошла эти семантические оценки; их нужно прогнать после доступа к Codex.
