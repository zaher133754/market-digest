# Многоступенчатая аналитика через ChatGPT Codex

Активный конвейер: `reports/analytical_pipeline.py`, подключён в `application.py`.
Предыдущие схемы и конвейеры сохранены для совместимости, но runtime их не использует.
Сбор Telegram и транспорт отправки не заменены. Оба вида отчётов загружают папки
«Посты» и «Чаты» за одинаковые 24 часа; source_kind сохраняется у каждого сообщения.

## Модели и авторизация

- Research/extraction, глобальное объединение, сравнение суток и аудит:
  `gpt-6-luna/high`, резерв `gpt-5.6-luna/high`.
- Финальная аналитическая записка: `gpt-6-astra/high`, затем `gpt-6-sol/high`,
  затем текущая `gpt-5.6-luna/high`.
- Codex CLI >=0.153.0; Docker закрепляет 0.157.1.
- Только существующий ChatGPT login. API keys удаляются из окружения дочернего
  процесса; `forced_login_method=chatgpt`, `model_provider=openai` переданы явно.
- `model_verbosity=medium`, `--output-schema`, повторная Pydantic-валидация.
- Веб, shell, приложения, plugins, hooks, multi-agent, browser/computer use
  выключены; ephemeral и read-only; контент передаётся через stdin.
- Плохая схема/нарушение доказательств не запускает fallback. Ошибка доступности
  CLI/таймаут переключает маршрут. Все модели недоступны — уведомление без выпуска.
- Успешная модель и попытки fallback сохраняются и видны в отчёте.

## Этапы

1. Каждое сообщение технически делится на части при необходимости. Все символы
   сохраняются. Для каждого part_id Luna обязана вернуть ровно один disposition:
   useful/noise/advertising/duplicate с причиной. Релевантность локально не решается.
2. ResearchCluster содержит тему, краткое описание, факты и точные цитаты,
   интерпретации, bullish/bearish/neutral аргументы, активы, все message_refs,
   группы зависимых первоисточников, число независимых групп, важность 1–10,
   уверенность 0–1, новизну, сравнение периода, настроение и триггеры.
3. Иерархическое объединение обязано покрыть каждый входной кластер и сохранить
   объединение всех message_refs. Все цитаты проверяются как точные подстроки
   исходного текста. Пересказ/копия не должен увеличивать число независимых групп.
4. Сравнение с предыдущим исследованием выполняет Luna, в том числе новизну тем.
   При отсутствии базы `is_new=null`, а не выдуманная новая информация.
5. Astra получает только исследование, каталог доказательств, метаданные текущего
   окна и предыдущую записку. Полный сырой массив в этот маршрут не передаётся.
   Выход — AnalyticalMemo: настроение, динамика тем, консенсус, до 5 главных тем,
   до 4 закономерностей, до 3 разногласий, до 5 триггеров, главный вывод, мысль дня.
6. Luna проверяет все утверждения пакетом/пакетами, по исходным сообщениям и истории.
   Для оригиналов длиннее 6000 символов аудит получает точные выдержки вокруг
   цитат (500 символов контекста с обеих сторон). Выдержки явно помечены.
   Неполный аудит, провал любого утверждения или невалидная схема блокируют выпуск.
7. Только проверенная записка вместе с исследованием сохраняется в JSON и отдаётся
   транспортному слою. Сохранение происходит до отправки, поэтому /history — это
   история проверенных записок, а не гарантия успешной Telegram-доставки.

Количество сообщений/источников выводит приложение из фактической загрузки.
Оно не используется как доказательство правоты. Индекс без подтверждений из чатов
запрещён. Утверждения несут явные типы: fact, source_opinion, forecast, emotion,
model_interpretation, synthesis. Связи и причинность проверяет AI-аудит;
технические проверки не могут доказать причинно-следственную связь.

## История и сравнимость

`RESEARCH_HISTORY_PATH` в постоянном volume хранит 35 дней исследований,
коротких цитат, каталог ссылок, итоговые записки и использованные модели.
Исходные полные тексты туда не пишутся. Запись атомарная через flush/fsync/replace.
Повреждённая история вызывает ошибку, не считается пустой историей.

База сравнения — ближайший отчёт того же вида, который закончился не позднее
начала текущего окна; допустимый разрыв <=6 часов. Перекрывающиеся ручные выпуски
не подходят. При отсутствии сопоставимой базы это явно указано. Предыдущий
индекс читается из сохранённой записки, а стрелка изменения вычисляется кодом.
Это экспертная оценка настроения выборки, а не статистический индекс всего рынка.

## Ограничения и тесты

При превышении контекста выполняется иерархическое объединение. Если его нельзя
завершить без потери ссылок, запрос завершается контролируемой ошибкой. Ни исходные
сообщения, ни кластеры не отбрасываются молча. Историческая база и структурированные
данные тоже проверяются по лимиту входа аналитика.

AI-аудит может ошибаться; утверждения Telegram не становятся биржевыми фактами.
Нет внешних котировок, OCR и мультимедиа. Сам CLI не экспонирует `store=false`;
правила хранения провайдера определяются настройками ChatGPT/Codex. Эту гарантию
из прежнего Responses API режима нельзя обещать для CLI.

`tests/unit/test_analytical_agent.py` проверяет разделение маршрутов, покрытие
входа, запрет выдуманных цитат, fallback и его раскрытие, остановку при провале
аудита, сохранение/выбор истории, отсутствие ложной динамики, разделение источников
настроения и отсутствие сырых сообщений в запросе Astra.

Официальные справки: [модели](https://learn.chatgpt.com/docs/models),
[model/list](https://learn.chatgpt.com/docs/app-server),
[автоматические вызовы](https://learn.chatgpt.com/docs/non-interactive-mode).
